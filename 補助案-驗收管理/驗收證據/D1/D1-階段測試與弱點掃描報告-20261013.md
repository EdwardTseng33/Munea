## 三、部署時掃描與每月掃描（自動化）

新增 `.github/workflows/security-scan.yml`：
- **每次提交／每個合併請求**：npm audit（嚴重／高直接擋下）、pip-audit、Trivy 檔案系統掃描、Dockerfile 設定掃描、**建 Cloud Run 映像並掃描**（與正式部署同一份 Dockerfile）。
- **每月 1 日**自動再掃一次，報告留存 400 天。
- 嚴重／高風險未修即紅燈，無法合併——這就是「部署時掃描」落地的方式。
- **第一次自動掃描結果（2026-10-13，GitHub Actions run 38411842193）**：套件層 0 弱點；Trivy 檔案系統掃描先抓到 iOS 原生殼仍釘 Capacitor 8.4.1（同一個嚴重級漏洞的第二個落點）→ 已釘 8.5.3；設定掃描抓到五份 Dockerfile 全用 root 跑（DS-0002 高）→ 引擎、總機、顯示卡管家三個 Cloud Run 容器改用非 root 帳號（munea，uid 10001），GPU 備援印象檔登記為已知接受風險（理由寫在 workflow 裡、排 D2 修補期）。修完全部綠燈。
