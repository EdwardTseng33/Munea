## 二、更新的方法：只改該改的格子

### 第 1 步：寫更新單

編輯 `updates.json`：

```json
{
  "note": "這次改了什麼，一句話",
  "rows": {
    "C1-2": { "狀態": "進行中", "完成%": 0.9, "備註": "……" },
    "D1-1": { "完成%": 0.8 }
  }
}
```

編號就是表上「編號」那一欄（A1-1、C1-2、M-2……）。
欄位名要跟表頭一模一樣：`狀態`／`完成%`／`備註`／`開始`／`到期`／`負責`。

### 第 2 步：先預演

```bash
cd "E:/Claude/Munea/補助案-驗收管理" && python update_progress.py --dry-run
```

會列出每一格「原本是什麼 → 要改成什麼」。看過沒問題再下一步。

### 第 3 步：寫回

```bash
cd "E:/Claude/Munea/補助案-驗收管理" && python update_progress.py
```

它會：下載雲端最新版 → 只改指定格子 → 寫回同一份。
**檔名、連結、位置都不變，資料夾不會多出東西。**

## 三、鐵律（踩過才立的）

### 🔴 絕不可以拿本機重生的版本覆蓋雲端

2026-08-10 差點踩到：我照 8/07 的舊清單做了一份本機版，正要覆蓋上去時發現雲端那份在 17:34 剛被改過——Edward 把八月完成線由 8/31 延到 9/5、日期整批往後調、A1 題庫加了「要補約 20 題純日常」的註記。直接覆蓋等於把這些全抹掉。

**所以永遠是「下載 → 改格子 → 寫回」，不是「重生 → 覆蓋」。**

### 🔴 一個工作段落結束才更新，不是每改一格就傳

8/10 一天生了四份多餘的檔案被念。現在只有一份，更新頻率也收斂成「一個段落結束才動」。

### 🟡 更新完讀回來確認

寫回之後把檔案抓下來看一眼那幾格對不對。工具回報成功不等於內容正確。
