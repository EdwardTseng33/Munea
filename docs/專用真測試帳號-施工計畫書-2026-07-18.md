# 沐寧 Munea · 專用真測試帳號 施工計畫書

> 2026-07-18 · 沙利曼 Gate 0 設計 review + 安全鐵律 · Edward 拍板 Ⓐ
> 目的：讓開發者/驗收（及 Apple 審查員）能用一個**真的、專用的**帳號撥通完整語音通話，而**不重開假證後門**。

## 背景（已讀碼查證）
- 「開發者帳號」快速登入造的是本機假證 `dev-local-token-<id>`（`web/src/auth.js:36-52`），非真 Supabase JWT。
- 通話總機 `/v1/calls`（`gateway/gateway_server.py:306-320`）第一步把 token 送 Supabase 驗證，假證必被 401 → App 登出掉回按鈕。這是 Build 43 補的安全洞（假證可冒充任意 user 撥號），**是紅線、不能拆**。
- 現成三道牆：① 正式 IPA 出貨門 `scripts/ios-export-app-store.sh:66-89` 強制 dev 旗標全 false；② `ios/App/App/public/` 與 `.env*` 已 `.gitignore`；③ 總機 Supabase 驗證。
- `--gateway` profile 已是半成品（autoSignIn/bypass 皆 false、走真總機），只差「灌真帳號 + 讓開發者鈕真的登入」。

## 1. 測試帳號
- **環境（硬約束）**：必須開在**東京正式 Supabase `fespbkdwafueyonppzwq`**（總機驗正式、正式包釘東京、Apple 審查跑正式線；開在 staging/雪梨＝撥不通）。
- **數量（沙利曼建議 B）**：
  - A：一個 `review@munea.net`，審查＋開發共用（簡單但送審期易被污染）。
  - **B（建議）**：`review@munea.net`＝Apple 審查專用、常滿、密碼穩定；`dev@munea.net`＝開發日常、隨便燒。多開一個成本近零，換「送審那刻 demo 帳號一定撥得通」。
- 都用 `@munea.net` 信箱、帳密登入（Apple 審查要帳密）、標 `app_metadata.role='qa_review'`、**不綁真人家人圈、不填真個資**。

## 2. 點數
- 管道：`POST /credits/grant`（`engine/server.py:7096`，需 `X-Munea-Admin-Token`）。每筆自動寫稽核事件。
- 常態上限 **500 點**；餘額 <100 補回 500；**單月硬上限 2000 點/帳號**（防外流燒錢，寫進補點小工具）。
- `review@munea.net` 送審前補滿 500、鎖住不開發使用。點數要灌對後端（正式帳本）。

## 3. 「開發者登入」按鈕改法
- `--gateway` profile 新增 `testAccountEmail/Password`（值從 build-time env 注入、**不寫死原始碼**）。
- 開發者鈕改走 `supabaseClient.auth.signInWithPassword(...)` 真登入（拿真東京 JWT）→ 過總機領證 → 撥通完整流程。
- **保留**假證/fixture 路徑做**純離線 UI 測試**（已被出貨門擋在正式包外）；文字聊天的 `MUNEA_ENABLE_DEV_AUTH_BYPASS` 維持 staging/prod 皆 false。界線：**假證可測 UI/本機文字，永不碰總機**。

## 4. 🔴 安全鐵律（機械強制）
**必須**：測試帳密只從 build-time env（`MUNEA_TEST_ACCOUNT_EMAIL/PASSWORD`）或 gitignored `.env.local` 注入、只寫進未入版控的 `auth-config.js`；**擴充 `ios-export-app-store.sh` 出貨門**，正式 IPA 若含測試憑證 pattern（`testAccountEmail/Password`、`@munea.net` 測試帳號）→ `exit 1`；測試帳號可即時 ban／改密。
**禁止**：憑證寫入任何 git 追蹤檔；`MUNEA_ENABLE_DEV_AUTH_BYPASS=true` 進 staging/prod；帳密對外散佈（僅開發包/TestFlight/Apple 審查欄）。
**🔴 紅線**：絕不重開假證後門——任何讓 `dev-local-token-*` 通過總機的路徑一律禁止。撥通靠真帳號真 JWT，不是放行假證。

## 5. 外洩爆炸半徑
憑證外流最壞＝單一帳號**封頂點數（≤500 常態／≤2000 月）**被燒掉，bounded 可停損；拿不到他人資料（user scoped）、無法造點數（另需 admin token）、無真人家人圈可騷擾、無真個資。可即時 ban／改密。

## 6. 包版影響 + 依賴順序
- **影響包版**（動 `web/src/auth.js`、`app.js`、`index.html`）：施工前先在 STATUS.md 登記（認領人/檔案/版號/需 cap sync＋Mac 重打包），做完回報。
- **需正式權限（Windows/gcloud 車道）**：東京正式 Supabase 開帳號 + `/credits/grant` 灌點（需 `MUNEA_ADMIN_API_TOKEN`）。
- **需 Mac 車道**：cap sync（東京設定）→ `--gateway` 注入 → Archive → 開發包安裝驗證。
- **先後鎖**：帳號＋點數（正式後端就緒）→ 才有真憑證可注入 build → 才能撥通驗收。

## 7. 工時（總 M ≈ 城堡 2–4 小時，卡點在正式權限與 Mac 打包等待）
1. 【Windows/正式權限·S】東京正式開 `review@`（＋選配 `dev@`），標 role、不綁家人圈。
2. 【Windows/正式權限·S】`/credits/grant` 灌 500 點 + 補點小工具（含 2000/月硬上限）。
3. 【STATUS 登記·XS】開工前登記包版影響。
4. 【Windows/前端·M】改 `auth.js` 新增 `signInWithTestAccount()` + 開發者鈕改呼它；profile 加憑證欄位（取自 env）。
5. 【Windows/安全·S】擴充出貨門新增「測試憑證不得進正式包」檢查 + 用假造正式包驗證會 exit 1。
6. 【Mac/打包·M】東京設定 cap sync → `--gateway` 注入 → Archive → 開發包用 `review@` 帳密實測撥通。
7. 【驗收·S】正式包出貨門對測試憑證會紅 + 開發包能撥通 + Apple 審查欄填 `review@munea.net`。

**沙利曼結語**：這不是開後門，是「用一個封頂、可停損、被出貨門機械擋在正式包外的真帳號走正門撥通」。假證碰總機那道牆一格都不准動。
