# 開帳與個人資料重整 · 需求單（2026-07-24）

> Edward 2026-07-24 中午拍板。背景：原 onboarding（web/onboarding.html 五步）被判定「App 上的設計有問題」——裝機感、岔路多、且第 1 步問的稱呼/名字/年紀/住在**從未存檔**（裝飾格）。個人資料 modal 欄位齊全但**只存 localStorage、無雲端同步**。

## 拍板結論（五條）

1. **迎賓流程整個退役**：登入（Google/Apple）→ 直接進首頁。不再有「幫誰裝／自己用」岔路、不再有任何多步設定精靈。onboarding.html 停用（路由不再導向；檔案退役處理方式由實作者判斷）。
2. **登入即免費會員**：登入當下自動建帳＝免費方案（帳號初始化從原本 onboarding 內搬到登入成功路徑），首頁明示「免費會員」身分，走既有免費體驗規則（方案免費＝5 分鐘體驗、不看錢包）。
3. **首登彈一次個人資料卡**（Edward 明確要的）：登入成功、首頁已渲染在背後，疊彈**既有的 profileModal**（不是新流程）：
   - 預填：名稱從 Google/Apple 帳號帶入。
   - 只求三格：家人稱呼（怎麼稱呼你）、出生年、縣市。照片等其他欄位照舊存在但不強調。
   - 明顯「先跳過」；填完或跳過後**永不再自動彈**（一次性旗標）。
   - 卡上一句價值說明：「填了這些，寧寧會用你習慣的稱呼、合你的節奏跟你說話，也能報你那邊的天氣。」
   - 跳過者：首頁保留「讓寧寧更認識你」小卡（點開同一張 modal）；寧寧通話中不知稱呼會自然問（人設已有「不確定不亂猜」規則）。
4. **個人資料上雲同步**（核心工程）：
   - pfSave 從「只寫 localStorage」改為「寫本機＋寫雲端」（經 Brain 寫東京 Supabase；離線時先本機、連上後補送）。
   - 資料表：persons 延伸（暱稱/出生年/地區欄位，新 SQL 檔，遵守既有 RLS 慣例）。⚠ 正式庫跑 SQL＝Edward 的車道，PR 只附檔與說明。
   - App 啟動時拉雲端資料合併（較新者勝）；既有用戶本機資料首次啟動後上傳。
   - **餵給寧寧**：通話開始時稱呼/年紀/地區到位——稱呼與地區走既有參數路；年紀接 PR #243 的三層節奏參數接口（年齡→講話節奏預設），此段依賴 #243 合併，未合併前先把資料通道做好。
   - 照片第一版不上雲（工程與隱私面都小很多）。
5. **AI 服務同意卡搬家**：從 onboarding 末步搬到「第一次按聊聊」時彈（不同意不能通話；同意過永不再彈）。同意文字要涵蓋「個人資料雲端同步」項——**措辭請沙利曼過目**（Gate 5）。

## 驗收條件（AC）

- 新帳號：Google/Apple 登入 → 首頁直達（無任何精靈頁）→ 個人資料卡自動彈（帶預填、可跳過）→ 首頁顯示免費會員。
- 填了稱呼/出生年/縣市 → 換裝置登入同帳號資料都在；通話中寧寧用對稱呼、報對縣市天氣。
- 跳過 → 首頁有「讓寧寧更認識你」小卡；不再自動彈。
- 第一次按聊聊 → 同意卡彈出；不同意不能通話；同意後不再彈。
- 舊用戶（已跑過原 onboarding／已填過資料）：不彈個人資料卡、不彈同意卡（既有同意紀錄有效）、本機資料自動上雲。
- 測試：新增路徑有測試蓋（登入直達/一次性旗標/合併規則「較新者勝」/同意閘），跑 test:launch 全綠。
