## 「登入」這一步的真相——不是真帳號登入，要講清楚

這支 debug APK 之所以一開就是首頁、沒有出現登入畫面，**不是因為關掉了 `MUNEA_REQUIRE_AUTH`**
（查過：這個環境變數只存在 `engine/server.py`／Cloud Run 部署腳本，是後端 API 要不要驗 token
的開關，跟這支 App 會不會顯示登入畫面完全無關），**也不是走訪客模式**（訪客模式沒有已登入
狀態、首頁會是空的）。

真正的機制：借用 iOS 既有的「直連測試包」腳本（`scripts/enable-ios-development-profile.mjs`），
透過 `npm run android:dev-profile:direct` 改生成出來的 `android/app/src/main/assets/public/src/
auth-config.js`，注入 `window.MUNEA_DEV_CONFIG = { enabled: true, autoSignIn: true, ... }`。
`web/src/auth.js` 的 `init()` 一看到 `autoSignIn === true` 就直接呼叫
`signInAsDeveloper()`——**這是在 App 本機合成一個假的 session 物件（`access_token:
'dev-local-token-...'`），完全沒有呼叫真正的 Supabase，也沒有用到任何密碼或金鑰**。同一套設定
也種了假家人資料、700 點數、任務清單（`seedFixtures: true`），讓首頁跟聊聊頁有內容可以看、
可以點。

**這份測試證實的是「自動登入機制本身有效、能讓 App 進到已登入狀態」，不是「真帳號登入流程
測試過」**——真帳號登入（Google/Apple 真人走 Supabase）完全沒測到，留給下面「真機實測欄位」。

## 這輪修掉的東西（上一輪的已知問題）

連續前面幾輪 CI，有 3 輪卡在同一點：點「聊聊」分頁時，App 自己彈出一張獨立的「開場三頁故事卡」
（`web/src/app.js` 的 `openOnboardingIntro()`／`runBootSplash()`，啟動後 2.4 秒自動彈出，完全不看
任何開發設定），故事卡「下一步」按鈕的螢幕座標剛好蓋住底部導覽「聊聊」分頁——用 accessibility
dump 的座標數字直接證實重疊，不是臆測。

這一輪的修法：在 `android:dev-profile:direct` 注入的設定檔裡多加一行
`localStorage.setItem('munea.onboardingIntroSeen.v1', 'true')`，純粹是改「生成出來的測試設定
檔」，**沒有動 `web/` 的 App 邏輯一行**。效果：故事卡再也不會彈出，這輪三個 job 全綠。

## 待修缺口（這支 PR 不處理，寫給之後的人）

**兩套開場機制的 key 沒對齊**：舊版迎賓精靈用 `ONBOARDING_COMPLETED_KEY`
（`munea.onboardingCompleted.v1`），新版三頁開場故事卡用完全不同的
`ONBOARDING_INTRO_SEEN_KEY`（`munea.onboardingIntroSeen.v1`）——`web/src/app.js` 裡自己留了註解
說這是「刻意不重用」。問題是：**direct 測試包的 `skipOnboarding: true` 只蓋到舊版那個 key**，
蓋不到新版故事卡。這代表任何人（不只是這次的自動化腳本）第一次用 direct 測試包登入，都會被
故事卡擋一次——這次是在測試腳本這端用注入 localStorage 繞過去，但 **App 本身這兩套 key 沒對齊
的狀態還在**，建議之後在 `web/src/app.js` 端把 `skipOnboarding` 順便蓋掉新 key，一次解決。

## 已知限制

1. **模擬器沒有真麥克風**（`-noaudio`）——這次測試只走到「同意畫面」那一步，還沒機會驗證
   真的點「I understand. Start talking」之後，連不上真語音的時候畫面會顯示什麼。
2. **這個 GitHub Actions runner image 的模擬器版本（37.2.12.0）不接受 `-prop persist.sys.*`
   開機參數**（只收 `qemu.*` 開頭），原本想釘 `zh-TW` locale 失敗；改成腳本同時給中英文候選
   字串繞過去（已驗證兩種 locale 都接得住——這幾輪 CI 有時候命中中文「聊聊」、有時候命中英文
   「Talk」，locale 本身在這個 runner 上不穩定，但自動化腳本不受影響）。
3. **`--gateway`（真測試帳號走真 Supabase 登入＋總機領證）這條路這次沒測**：需要
   `MUNEA_TEST_ACCOUNT_EMAIL`／`MUNEA_TEST_ACCOUNT_PASSWORD` 這組 GitHub Actions secrets，
   目前沒有設定，所以沒有建立、也沒有嘗試自己生一組密碼放進去。
4. **軟體渲染（swiftshader）在 CI 上偶發 GPU context 搶佔錯誤**（前幾輪出現過一次黑屏截圖，
   最終這輪沒再出現）——這類底層渲染抖動在軟體渲染的模擬器上是已知常見現象，不是 App 的問題。
