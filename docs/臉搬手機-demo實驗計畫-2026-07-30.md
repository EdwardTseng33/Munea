# 臉搬進手機 · Demo 線實驗計畫（2026-07-30 立案）

> Edward 7/30 拍板：「可以實驗用新人物推進，但先放到 demo 那條路線上可以看成果」。
> 正式線（寧寧擬真臉）完全不動；本實驗全程住在 demo 線。

## 一句話說這個實驗

把「會動嘴的臉」從雲端顯示卡搬進手機瀏覽器——用「聲音→嘴型」的動畫做法，
驗證三件事：**順不順、像不像人、成本是不是真的歸零**。

## 為什麼值得（對照現況）

| | 現況（雲端擬真臉） | 實驗目標（手機動畫臉） |
|---|---|---|
| 同時服務人數 | 一張 4090 兩席 | **無上限**（每支手機自己畫） |
| 每分鐘成本 | 約 NT$0.2/席 | **0** |
| 網路不好時 | 臉斷、嘴不同步 | **嘴型永遠貼著聲音**（同一台手機上畫的） |
| 擬真度 | 照片級 | 動畫級（高品質 2D 角色） |

## 做法（三步、全在 demo 線）

**第 1 步 · 技術骨架（先用簡單圖形驗管線）**
- demo 頁新開一條「動畫臉」模式：拿現有 demo 通話的聲音流，
  在瀏覽器裡即時分析出 8-12 種嘴型（業界標準做法），驅動畫布上的角色開合嘴
- 這一步用簡單佔位圖形就好——驗的是「嘴型跟得上聲音、每秒 30 格不掉幀」

**第 2 步 · 新人物美術**
- 依 Edward 指示用**新人物**（不動寧寧的擬真人設、不跟正式線打架）
- 素材走城堡生圖規矩：主對話生圖 → 女巫視覺關 → 才上 demo
- 需要的素材：一張立繪＋8-12 張嘴型差分（同一張臉、只有嘴不同）＋眨眼 2 張

**第 3 步 · 給 Edward 看成果**
- demo 頁併排兩個模式：雲端擬真臉 vs 手機動畫臉，同一通話同時動
- Edward（可帶真長輩）用眼睛投票：動畫級的溫度夠不夠？

## 明確不做的

- 不動正式線、不動寧寧人設
- 不自研「手機上跑照片級擬真」（論文級工程，等開源成熟再評）
- 不在這個實驗裡談品牌切換——先看成果再說

## 成敗判準

- 技術：手機瀏覽器 30fps 不掉幀、嘴型延遲 < 100ms、CPU 佔用可接受
- 體驗：Edward 主觀「有溫度、不出戲」；有機會給真長輩 A/B
- 若過關 → 才進入「要不要當低成本量產層」的產品討論（與擬真層並存分級）
