## 一、往內看 · 正式系統健康度（卡西法）

**總評**：程式碼本身大多健康、核心設計穩固。真正的風險不是「寫得對不對」，是**「新修好的東西還卡在原始碼、沒送上正式線」**——一次雲端聯合部署可同時解掉下面三個 🔴。

### 🔴 阻斷上線／送審（3 件，指向同一個動作＝一次雲端部署）
1. **點數發放還是舊制**。origin/main 原始碼、App 畫面、蘋果後台都已是新制（Plus 100／Pro 200／點數包 100/300/600/1000），但**正式與測試 Brain 服務跑的還是 7/13 舊制（Plus 150／Pro 300）**。證據：正式 Brain=`1.0.36@d6a72a1`、pricing commit `5156d91` 不是它的祖先。後果：**若現在有人用 Build 47 買「100 點 NT$790」，伺服器實際發 150 點（多發 50%、財務對不上）**。根因＝雲端服務未重新部署（非本機檔案）。
2. **7/17 晚間所有聊聊／健康修正尚未上線**（拿掉通話中即時查詢 793ecdc、所在地修正 f561595、情緒卡雲端 None-safe、AI 限流護欄等全在原始碼、未進任何跑動服務）。對外 STATUS 聲稱「已修好」與正式機實況有落差。
3. **開發測試後門 `/chat-test` 在正式與測試 Voice 服務公開可存取（HTTP 200）**，內容含假身分自動登入 + 自動點「開始通話」。`live_voice_server.py:177` 無條件回應。緩解：Brain 端 `MUNEA_ENABLE_DEV_AUTH_BYPASS=false` 會擋假 token，但 Voice 自身驗證鏈未逐行覆核（列給沙利曼複核）。修法在 PR #181→#182，仍 Draft。

### 🟡 該修、不阻斷
- **0 點按撥號誤顯示「撥通中」＋ Apple 帳號綁定衝突提示不清**：PR #174／#175 已 rebase、CI 綠，卡真機 Gate、仍 Draft，未進 Build 48。
- **Pro 年繳金額分歧**：6 份文件（含 billing 權威檔）一致 NT$11,500，且與「省 20.1%」數學吻合；**只有 STATUS 一行寫 9,590**（7/8 建商品當下紀錄）。設計意圖清楚指向 11,500，9,590 極可能是建商品當下暫存/手誤。**需真人登 App Store Connect 現場核對**後更正 STATUS。
- **東京 Supabase 017/018/019 migration 是否真的跑過＝unknown**，需有權限者唯讀查 `entitlement_policy_versions` 現行 active 版本是否為 019 的 version 4。

### 🟢 健康、找不到明顯問題
通話門禁開關部署預設安全（不會重演 7/16 70 分鐘事故）／通話計費伺服器權威、逐分鐘扣點有 advisory lock + idempotency／Apple Health 接口誠實、隱私聲明一致／情緒卡 moodKey 三層防護／邀請碼存取控制 6/6 + 防爆破合理／蘋果簽章 JWS 驗證 14/14、金流寫入收在 admin token 後。

## 二、往內看 · 自動化測試缺口（馬魯克）

**結構性根因**：`npm run test:launch`（44 支測試）**沒有被任何 CI 呼叫**，main 分支**沒有「測試綠燈才能合併」保護**（gh api 回 404）。每次 STATUS 寫「15 支全綠」都是人手動自律，不是機器擋的。**卡西法還發現：test:launch 現在對 origin/main 是紅燈**——`test-voice-launch-policy.js:145` 斷言字串沒跟上 793ecdc 的程式改動（其餘 43 支全綠）。

### 最該補的缺口（依風險）
- **P0 危機偵測是孤兒測試**：`test_guardian_crisis.py`（19+21 情境，判「我不想活了」→critical）**不在任何自動流程**。語音腦一重構就可能悄悄弱化、無告警。這是四功能中風險最高的單一缺口。
- **P0 通話門禁/Gateway/GPU 調度 13 支測試從未進自動流程**（正是 103 號 70 分鐘撥不通的那一層）；且 release-settings 只驗原始碼字串、不驗實際部署的環境值。
- **P0 邀請碼防爆破無測試**（7/11 P0 安全修復無回歸守門）。
- **P1 平安燈三態、家庭帳本彙整、BRAIN_URL 打包後真值** 皆無自動守門。

### 建議工具改進（依槓桿）
1. **把 test:launch 掛進 CI + 開 main 分支必過保護**（最高槓桿，測試品質不差、只差沒人逼它跑）。
2. **危機偵測立刻補進 test:launch**（純函式、零外部相依、成本近零）。
3. **建「部署後真值稽核」**：用 `gcloud run services describe` 讀實際生效環境值比對白名單，掛進 5 分鐘看門狗——同時堵 103 門禁漂移與 BRAIN_URL 錯連。
4. **selftest.html 改 puppeteer 無頭執行**，把手動 20 條變 PR 自動關卡。
5. 區分「靜態字串比對」與「真行為」兩層，CI 至少強制行為段必過。

## 三、往外看 · 提升訂閱意願（霍爾 + 蕪菁頭，兩人獨立查、撞同一結論）

**核心洞**：產品整個 onboarding 都在跟「掏錢的子女」講話，但**現在賣的是「聊天分鐘數」、品牌講的是「會記得你、在乎你的人」——兩件事沒對上**。記憶引擎、情緒監測、平安燈都有底子，卻被藏在背景、沒包裝成「付這筆錢換到的東西」。而且 Plus vs Pro 差異只有「量」（150 vs 300 點）＝恐懼驅動、非渴望驅動，續訂天生弱。對標：ElliQ 家人端價值＝「異常才主動說」、Replika 續訂第一理由＝「她真的記得我」——兩者我們都「有底子、沒兌現」。

**最大結構漏洞（蕪菁頭）**：「免費額度用完」發生在**長輩手機上**，但決定付錢的是**子女**——兩端沒接起來＝安靜流失，連抱怨都不會出現。

### 建議（依對訂閱意願影響）
1. **異常關懷主動通知家人**（連續沒聊/情緒轉差/漏藥 → 主動推播子女）。把產品從「陪聊工具」升級成「守護系統」，取消訂閱＝關掉安全網，黏著最強。工時 M。
2. **家人安心週報卡**（這週聊幾次/心情/掛心的事，可轉傳）。讓子女看得到錢花在哪，直接解續訂猶豫。心情週報已有底，擴充。工時 M。
3. **讓「她記得你」被感覺到**（聊天主動引用幾個月前的事：孫子名字、怕打針）。memory_engine.py 已存在，重點是「用出來」而非重蓋。工時 M。
4. **免費用完 → 同步通知子女**（接住決策者，補上最大沉默流失點）。工時 S-M。
5. **付費牆文案：功能清單改恐懼場景**（「媽媽血壓異常你會第一個知道」取代「看更久的紀錄」）。`paywall_shown` 已有埋點、改完直接看轉換。成本最低、槓桿高。工時 S。
6. **第一通免費電話可靠度當北極星指標**（過去 12 個版本都在修同一接通環節＝地基）。所有其他槓桿都建在「子女相信這東西可靠」上。
7. onboarding 第 3 步誠實標付費時機（別讓子女誤以為已邀請成功，事後被打槍傷信任）。

### 前 3 優先（合議）
① 異常主動通知 + 免費用完通知子女（1+4，把守護變剛需、接住決策者）
② 安心週報卡（2，讓錢花得看得見）
③ 讓記憶被感覺到 + 試用臨門一腳用記憶感動（3+文案，兌現品牌承諾、成本低）
