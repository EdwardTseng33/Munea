## 一、GPT-Live 是什麼（官方文，2026-07-08 發布）

兩項架構改變：
1. **全雙工**：邊聽邊講，每秒多次決定「說話/聆聽/暫停/插話/呼叫工具」；能「嗯哼」附和、用戶思考時安靜等待。
2. **雙腦分工**：GPT-Live 前台撐對話，深工作（搜尋/推理）委派背景 GPT-5.5，**處理的同時繼續交談**，好了接回。Edward 描述的「先講過場話→邊講邊查→順接三條」＝此架構的原生行為（模型被訓練先講 acknowledgment＋非阻塞工具呼叫）。
3. **關鍵現實：GPT-Live API 尚未開放**（開發者只能填表候補）→ 這顆引擎現在買不到。GPT-Live-1 為 ChatGPT 付費預設、mini 為免費版預設。發布時不支援視訊/螢幕分享。另有語音安全設計（自傷防護/情感依賴監測/危機轉介）與我們守護腦同方向，可當對外背書。

## 三、技術調研關鍵發現（2026-07 現況）

1. **⭐ 「邊講邊查」的 Google 正版＝Gemini 2.5 Flash Native Audio**：非阻塞工具呼叫（NON_BLOCKING＋WHEN_IDLE/INTERRUPT/SILENT 排程）、affective dialog（語氣隨情緒）、proactive audio（模型自決何時開口）**都只在 2.5 native audio**；我們用的 gemini-3.1-flash-live-preview 只支援同步工具呼叫。且 Vertex AI 上 **2.5 native audio 已 GA（含 SLA）、3.1 仍 preview**。→「要三大自然感功能＋穩定版」vs「要 3.1 低延遲新版」需 A/B 實測定奪。
2. **VAD 全套可調**：start/endOfSpeechSensitivity、prefixPaddingMs、silenceDurationMs（<500ms 會切碎句子）。已知 3.1 社群回報 bug：模型開口瞬間用戶已在講話時不發 interrupted。
3. **斷續根因（業界共識）**：Gemini Live 只有 WebSocket 接口（行動網路下無防抖、隊頭阻塞）；標準解＝**最後一哩換 WebRTC**（Pipecat/Daily/LiveKit 有現成 Gemini 整合），或用 ephemeral token 讓 App 直連 Google 省 Cloud Run 一跳。
4. **語速**：Live API 無語速參數（feature request 開著）；只能靠人設指令「慢、穩、短句」＋選穩重聲線；2.5 的 affective dialog 可輔助。
5. **成本**：Gemini Live 約 $0.023/分鐘雙向；OpenAI gpt-realtime-2.1（2026-07-06）已有原生 async 工具呼叫可當備選路（mini $0.60/$2.40 per 1M）。

## 四、長輩體驗研究（蕪菁頭 · 有文獻）

- 長輩句中停頓常超過一般輪替門檻→被搶話＝已發表的核心痛點；**搶話的傷害大於稍慢**（時間壓縮語音對老人理解傷害顯著；適當停頓反而助理解）。
- 解法不是只拉長沉默門檻，是「門檻拉長＋漸進式澄清」雙保險（聽不確定時問「不好意思，你是說誰？」）。
- 語速建議 100-125 wpm（一般成人 150-160）；停頓放語意邊界。
- 老人聽覺工作記憶約 3 個 chunk→**一次三條新聞上限合理**，但每條要短、條間停頓/確認，不能連珠炮。
- 過場話用完整句子講清楚「在做什麼」＞追求快——安心感優先於速度感。
- ⚠ 長輩被搶話不會抱怨、會自責然後默默少用→要監測「主動說話次數/使用頻率下降」當隱性警訊。
