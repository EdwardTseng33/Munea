## 1. 終局對焦（我們最後要成為什麼）

### 1-1. 終局一句話（提案，待 Edward 認可）

> **沐寧是每個家庭的「健康代理人」（Family Health Agent）：平時是最懂這家人的陪伴，就醫時刻是這家人最可靠的代言；當醫療體系逐步 agent 化，沐寧就是家庭端的預設節點。**

### 1-2. 三個身分定盤（終局最重要的三條線，定了就不再漂）

**定盤一 · 我們是「家庭端」的代理人，永遠不是醫院端的系統商。**
agent-to-agent 有兩端：醫院/診所端（supply side）與家庭端（demand side）。醫院端會有自己的系統與 AI（HIS 廠商、遠距平台、未來的醫院 agent——別人會做、輪不到我們做）。沐寧只做家庭這一端：**用戶自己的資料、用戶授權的代理、忠於家庭的利益**。這一條定了，三件事同時清晰——
- 法遵形態：我們是「用戶行使自己資料權的工具」，不是「醫療資料中介商」（避開電子病歷雲端服務商的監管形態，直到 C2 前都不碰）；
- 商業模式：付錢的是家庭（現行訂閱模式的延伸），不是醫院；
- 信任結構：醫師知道這份摘要「代表病人與家屬」，角色乾淨。

**定盤二 · 陪伴是根，代理是果——健康代理能力長在陪伴人格上，不另起一個工具 App。**
沐寧的靈魂（北極星四支柱：AI 智慧照護、家人互動、聊聊心事、全家健康管家）不變。健康代理是支柱一與四的深化，不可以吃掉支柱二三。落到設計上：**所有代理輸出都從寧寧（角色人格）口中/手中遞出**——摘要單是「寧寧幫你整理好的」、口袋問題是「寧寧幫你記的」，不是一個冷冰冰的表單模組。蕪菁頭的警告成立：就醫功能一旦做成冷工具，「像家人」的體驗就被稀釋，那是我們唯一輸不起的資產。

**定盤三 · a2a 的入場券不是技術，是「資料完整度 × 信任」——現在每一階都在累積入場券。**
醫療端的 agent 介面何時出現、長什麼樣，不由我們控制；但那一天到來時，**家庭端誰握有最完整、最即時、用戶授權的健康全貌，誰就是對接者**。所以 M1-M3（見 §6）的戰略意義不只是功能，是入場券累積。而沐寧累積資料的方式是獨家的：競品要用戶填表，我們的資料從天天的聊天與陪伴中自然長出來——**陪伴本身就是資料完整度的護城河**。

**定盤四（錨定）· 終局先是台灣形狀的。**
健保健康存摺、雲端藥歷、名醫文化、通訊診察治療辦法——我們的終局 v1 是「台灣健保生態的家庭端節點」，不是抽象的全球 a2a 夢。在地深耕即是壁壘；模組化出海（`聊聊模組化-多市場應用藍圖`）是之後換皮的事。

### 1-3. 終局不變量（到了終局也不變的事）

- **永不診斷、永不判讀、永不往下擋**——代理人「攜帶與轉達」，永不「判斷」。到了 a2a 階段也一樣：沐寧遞資料、接收醫囑、幫忙記住與執行，醫療判斷永遠在醫師端。
- 危機轉介（119/1925/113/家人）永遠保留、不因功能深化而外包。
- 用戶（長輩本人）永遠是資料的主人：看得到、關得掉、刪得掉。

## 2. 一句話憲法（每一階共用）

> **沐寧整理事實，醫師做判斷。**
> 沐寧的姿勢永遠是「資料夾＋秘書＋傳話筒」，永遠不是「判讀的醫生」。守住它，功能做多深都在安全側；越過它，合規難度整級跳。

Edward 那句「讓醫護做更精準更有效率的判斷」是**內部價值理解**；對外文案一律禁用「協助醫師判斷/診斷/更精準」句式——對外只說「幫你把狀況說清楚、資料帶齊、問題記好」。判斷的主詞永遠是醫師。

## 3. 紅線（沙利曼 · 先於一切設計）

1. **文案紅線**：對外禁用「協助診斷」「讓醫師更精準判斷」「臨床決策」等句式——會把沐寧推向臨床決策支援/智慧醫療器材（SaMD）認定範圍。
2. **不對稱鐵則（就醫建議唯一安全形狀）**：**只往上推、永不往下擋。** 可以說「建議盡快就醫/掛急診」，永遠不說「不用看醫生」「觀察就好」「應該沒事」。往下擋＝延誤就醫＝出人命＋醫材紅線。
3. **結構化嚴重度評估＝深水區**：「問幾題→給嚴重度分級」的 symptom checker 可能落 TFDA 智慧醫療器材軟體認定——做之前先過律師。衛教式導引（D2 形狀）在安全側。
4. **病歷/健康存摺＝特種個資（個資法§6）**：合法路＝當事人**書面同意**＋加密＋可刪除＋來源標記；同意設計需律師最終確認。與「長輩自己量→非特種個資」的既有保護傘是兩個世界，資料分艙要分等級標記、不可混存。
5. **醫師資訊只彙整、不評價**：只整理公開資訊（專長、學經歷、門診表），不排名、不打分、不說「這個醫生不好」。
6. **病歷的家人可見性要專屬分層**：不沿用「連結後健康數據全開」的既有拍板——精神科、婦產科、感染科等敏感紀錄不因家庭連結自動攤開（延伸 RLS L4 邏輯，落 schema 前與 Codex 協調）。
7. **機構介接前必過法遵**：沐寧一旦成為「病歷在醫院↔家庭之間流動的中介」，可能落入電子病歷相關雲端服務規範——C2 啟動前律師＋法遵盤點（配合定盤一，C2 之前我們始終只是「用戶自己的工具」）。

## 4. 差異化真相（為什麼這題是沐寧的）

- **醫師已經看得到健保雲端藥歷**（跨院用藥、檢驗）。把健保資料再印一次＝零價值。**沐寧的獨家＝雲端藥歷裡沒有的**：生活狀態變化（睡眠/食慾/活動）、症狀時間軸（「上週開始走幾步就喘」）、在家量測、用藥**實際**順從度、長輩在診間 3 分鐘講不清楚的脈絡。
- **沐寧是唯一天天跟長輩講話的**——症狀線索在聊天中自然出現、自然入帳，用戶零填表。記憶層＋感知層既有投資的直接變現。
- **門診真相＝3 分鐘**：摘要單必須**一頁、30 秒可讀**；細節放第二層（醫師想追問才翻）。

## 5. 規劃方法（怎麼規劃——四個原則）

**5-1. 從終局倒推（backcast），不從功能疊加。**
終局（家庭端健康代理人）需要四樣資產：①健康全貌資料 ②同意與授權基礎設施 ③遞交介面 ④家庭信任。每一階的任務都要能回答「這一步在累積哪一樣資產」，答不出來的功能不排。

**5-2. 兩軸矩陣定進度。**
- **資料完整度軸**：生活狀態 → 在家量測 → 用藥實況 →（跨過特種個資線）→ 上傳病歷 → 官方紀錄（健康存摺）。
- **就醫旅程軸**：日常累積 → 就醫前（該不該看/看什麼科/準備摘要）→ 診間（遞交）→ 就醫後（記醫囑/接提醒）→ 跨機構（a2a）。
終局＝矩陣填滿；每一階＝往右下多填幾格。現況（M0）已站住左上角：陪伴、記憶、感知、量測、用藥鬧鐘、守護腦紅旗。

**5-3. 閘門制：每一階只證明一個假設，閘門過了才燒下一階的錢。**
每階定義「要證明的假設＋通過條件＋失敗訊號」。假設沒證明就加碼＝把錢押在想像上；特別是 M2 之後開始燒律師費與 SDK 申請成本，必須等 M1 證明「就醫時刻真的有人要」。唯一例外：**便宜的前置可以先走**（律師一次性初診、SDK 資格查證——問路錢，不是蓋房錢）。

**5-4. 防漂移機制。**
每階收尾回對兩件事：①終局一句話（§1-1）②北極星四支柱。健康代理線只允許強化支柱一與四，若發現在吃支柱二三（陪伴/家人互動的體驗變冷、變工具），觸發蕪菁頭真相介入。

**M3 前置查證快查結果（2026-07-26 卡西法 · Edward 問「Apple 拿不拿得到健康存摺授權」）**：
- **Apple 這條路不通**：Apple Health Records（健康紀錄，FHIR 病歷介接）只開放美/英/加，台灣無任何醫院支援；Apple 在台灣能給的只有 HealthKit 量測數據（我們既有的 `Apple健康串接` 路線），不是病歷。
- **健保 SDK 正門是開的**：健康存摺 SDK 開放「合法登記的本國/外國公司」申請（陸資除外）→ 沐寧有公司主體即符合資格；用戶授權後可下載就醫/用藥/檢驗結果。
- **真門檻＝數發部行動 App 資安檢測 L2 證明**（正式申請必附）＋健保署簽約＋3 個月內上架證明——M3 的前置成本具體化為「資安檢測 L2」，且該認證與既有資安體檢方向一致、B2B 亦可複用。
- **過渡土路**：用戶自行從健保快易通下載自己的存摺資料→手動上傳（M2 形態），零申請門檻、體驗差，可當 M3 前的過渡。
- 沙利曼註：SDK 合法介接進來的資料**仍是特種個資**——紅線 4（書面同意＋加密＋可刪除）先就位，SDK 不替代同意設計。
- 來源：Apple Support（Health Records 地區清單）、健保署 SDK 健康服務連結介紹、iThome 報導、衛福部新聞稿（2026-07-26 查證）。

**排序邏輯（為什麼是這個順序）**：
1. **先價值後資料**：先讓就醫時刻產生看得見的價值（M1），用戶才有理由把更深的資料交給你（M2/M3）——信任是資料的前提，不是反過來。
2. **先自述後官方**：自述/自量（非特種個資）先跑通產品迴路，官方資料等法遵就位。
3. **先人手後機器**：遞交先走 QR/紙本（M4），機構介接等生態（M5）——我們不推生態、我們準備好等生態。
4. **紅線每一階同形**：不診斷、不判讀、只往上推，從 M1 到 M5 一個字不變。

## 7. 用戶真相（蕪菁頭 · 貫穿各階）

1. **做整理工的是子女，不是長輩**——摘要單必須零額外輸入、從日常聊天與量測自動長出來。
2. **醫師只看一頁**——超過一頁，功能對醫師端就死了。
3. **名醫推薦的信任反噬**——幫你查、陪你選、**不替你選**。
4. **滑坡防禦**——用戶一定會拍傷口問「嚴不嚴重」；出口永遠導向「幫你記下來去問醫生」＋紅旗往上推。**別做一個會讓長輩延誤就醫的貼心 AI。**
5. **工具化警報**——就醫功能若讓 App 變冷（支柱二三被吃），觸發真相介入（§5-4）。
