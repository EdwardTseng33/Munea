# 健康照護管家 · 就醫代理與就醫導引 — 方向與分階（2026-07-26）

> 緣起：Edward 2026-07-26 兩輪指示——①沐寧要能完整整理家庭成員的病歷資料（健康存摺）與生活狀態（日常健康數據、用藥、就診情況），就診前/時提供給醫生、診所、醫院、甚至遠距醫療，讓醫護做更精準有效率的判斷；②就醫判斷：該不該看醫生、該看什麼科、該看哪個醫生（依嚴重度、要不要動刀、口碑——台灣非常吃名醫）；③終局＝agent to agent，家庭 ↔ 醫院/診所。
> 本檔＝城堡圓桌結論：一句話定盤 + 紅線 + 四階分階 + 待 Edward 拍板。**方向文件，未動任何程式。**

## 1. 一句話定盤（整個功能的憲法）

> **沐寧整理事實，醫師做判斷。**
> 沐寧的姿勢永遠是「資料夾＋秘書＋傳話筒」，永遠不是「判讀的醫生」。
> 這條線就是特種個資保護傘與醫療法紅線的分界——守住它，功能做多深都在安全側；越過它（判讀、評估、建議治療），合規難度整級跳。

Edward 那句「讓醫護者能做更精準更有效率的判斷」是**內部價值理解**（我們相信整理好的資料確實會讓醫師更有效率）；但**對外文案與 App 內措辭一律禁用**「協助醫師判斷/診斷/更精準」這類句式（見紅線 §3-1）——對外只說「幫你把狀況說清楚、把資料帶齊」。判斷的主詞永遠是醫師，不是沐寧。

## 2. 兩條產品線（Edward 的兩點各自成線）

### 線一 · 就醫代理（整理 → 遞交）
日常累積（生活狀態、在家量測、用藥實況、聊天中自然聽到的症狀線索）＋官方紀錄（健康存摺/上傳的報告）→ 就診時長成一張**就診摘要單** → 由用戶親手遞給醫護（人手/畫面/QR，長線才是機構介接）。

### 線二 · 就醫導引（該不該看 → 看什麼科 → 看哪個醫生）
三層風險完全不同、拆開處理：
- **D1 紅旗急症**：胸痛/喘不過氣/中風徵兆 → 立刻就醫/119。守護腦已有（`emergency_terms` + 語音線字幕監聽），維持。
- **D2 科別導引**：衛教式「這類狀況一般看○○科」，預設答案永遠含家醫科選項、永遠附「不確定就先看一次最安心」。
- **D3 醫師資訊**：彙整公開資訊（專長、學經歷、門診表）幫用戶做功課——**姿勢待 Edward 拍板（§7-1）**。

## 3. 紅線（沙利曼 · 先於一切設計）

1. **文案紅線**：對外禁用「協助診斷」「讓醫師更精準判斷」「臨床決策」等句式——這類宣稱會把沐寧推向臨床決策支援/智慧醫療器材（SaMD）的認定範圍。對外只說「幫你把狀況說清楚、資料帶齊、問題記好」。
2. **不對稱鐵則（就醫建議唯一安全形狀）**：**只往上推、永不往下擋。** 沐寧可以說「這種情況建議盡快就醫/掛急診」，**永遠不說**「不用看醫生」「觀察就好」「應該沒事」。往下擋＝延誤就醫＝出人命＋醫療器材紅線，是這個功能唯一會出大事的方向。
3. **結構化嚴重度評估＝深水區**：做成「問幾題→給你嚴重度分級」的 symptom checker，可能落入 TFDA 智慧醫療器材軟體認定——**要做之前先過律師**。衛教式導引（D2 形狀）在安全側。
4. **病歷/健康存摺＝特種個資（個資法§6）**：醫師看診產生的紀錄，不管誰上傳都是病歷。碰它的合法路＝當事人**書面同意**＋加密＋可刪除＋來源標記；同意文件設計與適用範圍**需律師最終確認**。這與現有「長輩自己量→非特種個資」的保護傘是兩個世界，不可混存混用（資料分艙時要分開標記等級）。
5. **醫師資訊只彙整、不評價**：只整理公開資訊（醫院官網專長、學經歷、門診表），不排名、不打分、不說「這個醫生不好」——誹謗與公平性風險，且口碑資料來源合法性要先過。
6. **家人可見性要再分一層**：病歷比健康數字敏感。現行拍板（2026-07-01：連結後健康數據完整顯示）**不自動延伸到病歷**——精神科、婦產科、感染科等敏感科別紀錄不因家庭連結自動攤開，要有病歷專屬的分層開關（延伸 RLS L4 邏輯，落 schema 前與 Codex 協調）。
7. **終局的隱藏門檻**：若沐寧成為「病歷在醫院↔家庭之間流動的中介」，可能落入電子病歷相關雲端服務規範（衛福部有專門管制）。C2 機構介接啟動前必過律師＋法遵盤點——那是 B2B 形態的公司，不是消費 App 的延伸功能。

## 4. 差異化真相（為什麼這題是沐寧的，不是任何健康 App 的）

- **醫師已經看得到健保雲端藥歷**（跨院用藥、檢驗、影像）。我們如果只是把健保資料再印一次＝零價值。**沐寧的獨家＝雲端藥歷裡沒有的東西**：生活狀態變化（睡眠、食慾、活動）、症狀時間軸（「上週開始走幾步就喘」）、在家量測數據、用藥**實際**順從度（開了藥有沒有真的吃）、長輩自己在診間講不清楚的脈絡。
- **沐寧是唯一天天跟長輩講話的**——症狀線索在聊天中自然出現、自然入帳。競品要用戶填表，我們的表自己長出來。這是記憶層＋感知層既有投資的直接變現。
- **門診真相＝3 分鐘**：摘要單必須**一頁、30 秒可讀**。做成資料海＝醫師不看＝功能死。一頁放不下的細節放第二層（醫師想追問才翻）。

## 5. 分階計畫

### A · 看診秘書（v1.x · 不碰特種個資 · 可直接排）
| 項 | 內容 | 資料來源 |
|---|---|---|
| A1 就診摘要單 | 就診前自動生成一頁：主訴與症狀時間軸／在家量測近況／用藥現況與順從／生活狀態變化／想問醫生的問題。長輩字級、可出示可列印。 | 記憶層＋感知層＋健康數據，全部=用戶自述/自量/App 既有 → **非特種個資側** |
| A2 口袋問題 | 平常聊天聽到症狀疑問 → 寧寧「我幫你記下來，下次問醫生」→ 自動進清單（安全能力補齊計畫批次 1 #6 的兌現） | 對話 |
| A3 就診後記錄 | 回家後語音聊「醫生今天怎麼說」→ 記下重點、回診日/新用藥自動進提醒 | 用戶轉述（標記來源=轉述，非病歷） |

### D · 就醫導引（輕 · 與 A 並行）
- D1 紅旗 → 急診/119：**已有**，維持。
- D2 科別導引：衛教式＋家醫科預設＋「不確定就看醫生」永遠附上（紅線 2 不對稱鐵則）。
- D3 醫師資訊彙整：**待 §7-1 拍板後才動。**

### B · 病歷保管箱＋健康存摺（v2 · 特種個資 · 先設計後施工）
- 拍照/上傳藥袋、檢驗報告、診斷書 → OCR → 結構化（用藥清單、檢驗值時間軸），每筆標來源與資料等級。
- 健保署**健康存摺 SDK** 申請（用戶授權下載自己的就醫/用藥/檢驗紀錄——「用戶行使自己的資料權、沐寧代管」是對的姿勢；申請資格與條件需查證）。
- **前置四件**：①書面同意設計＋律師（紅線 4）②病歷分層開關（紅線 6）③schema 與 Codex 協調（RLS 文件卡點 B 同一題）④「拍照諮詢」出口全部導向「幫你記下來去問醫生」、不判讀（紅線 1/2）。

### C · 對外遞交 / agent-to-agent（長線）
- **C0 ＝ A 的摘要單本身**：診所不會為一個消費 App 接 API——a2a 的 v0 是一張紙/一個畫面/一個 QR，由用戶親手遞。最低科技、零整合成本、今天就通。
- C1：分享連結/PDF 給遠距醫療（通訊診察治療辦法已放寬，通道存在；合作形式待研究）。
- C2：FHIR（TW Core IG）機構級介接——B2B、需醫院合作＋資安認證＋紅線 7 法遵，**三年後的公司形態題，不是 v1 功能題**。

## 6. 用戶真相（蕪菁頭）

1. **做整理工的是子女，不是長輩**——摘要單必須零額外輸入、從日常聊天與量測自動長出來，否則沒人用。
2. **醫師只看一頁**——超過一頁的那一刻，這個功能對醫師端就死了。
3. **名醫推薦的信任反噬**——我們推薦、結果不好，帳算沐寧頭上。姿勢＝幫你查、陪你選、**不替你選**。
4. **滑坡防禦**——用戶一定會拍傷口/疹子問「嚴不嚴重」。產品要在設計上主動把出口導向「我幫你拍下來記好，看診第一個問醫生」＋紅旗時往上推，永不判讀、永不安撫式往下擋。**別做一個會讓長輩延誤就醫的貼心 AI。**

## 7. 待 Edward 拍板

1. **D3 醫師選擇的姿勢**：A案＝只彙整公開資訊、幫用戶做功課（風險低、蘇菲建議）；B案＝做推薦/排名（差異化強但誹謗、公平性、資料來源、信任反噬四重風險，且要另建口碑資料能力）。
2. **B 階段啟動時機**＝開始燒律師費＋送健康存摺 SDK 申請的時點：A 驗證後（蘇菲建議，先確認用戶真的用秘書功能）或平行啟動（快、但錢先出）。
3. **紅線 2 不對稱鐵則寫進 CORE/RED**（聊天/語音線共用底盤）：蘇菲判斷這是安全側的純加固、建議直接做——除非 Edward 有異議，排下一個施工單。
