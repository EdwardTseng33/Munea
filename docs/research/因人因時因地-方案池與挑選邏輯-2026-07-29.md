## 〇、現有設計缺什麼

7/24 決策模型已有：四張牌（人／境／心／史）、五步思考、時效軸（今晚／一週／慢養檔）、五維排序。
實際要落地時發現**缺兩個軸，而且缺的正是 Edward 這次點的重點**：

| 缺的軸 | 為什麼一定要有 | 不補會怎樣 |
|---|---|---|
| **① 解方類型偏好** | 台灣人對「怎麼調身體」的信念差異極大：有人只信西醫實證、有人非中藥不可、有人排斥吃任何藥丸只願改生活 | 給一個排斥保健品的人推鎂錠＝白講；給一個要快的人講「慢慢調理」＝他覺得你沒用 |
| **② 可執行性（他做得到嗎）** | 「固定時間起床」對退休長輩很容易，對輪三班的護理師是**做不到的正確答案** | 建議正確但做不到＝比不給還傷信任，他會覺得「你根本不懂我的生活」 |

原設計的「文化接受（食補>藥丸）」只有一句帶過，不足以撐起 Edward 要的「截然不同」。

## 一、資料結構：一個症狀 = 一個方案池，不是一條答案

每個症狀（例：失眠）底下掛 5–10 個**方案**，每個方案帶完整標籤：

```jsonc
{
  "id": "sleep-magnesium",
  "label": "睡前補鎂",
  "riskLevel": "L3",              // L1生活 L2食物 L3保健品 L4處方 L5急症
  "maturity": "🟡",                // 🟢已證實 🟡有苗頭 ⚪傳統經驗
  "timeToEffect": "一週",          // 今晚 / 一週 / 慢養
  "solutionType": "保健品",        // 行為調整 / 食補 / 保健品 / 中醫調理 / 就醫
  "effortCost": "低",              // 低（買來吃）/ 中（要改習慣）/ 高（要規律運動、要請假）
  "audience": ["worker", "elder"],
  "contraindications": ["腎功能異常", "低血壓", "孕哺"],
  "dailyCap": "250mg",
  "mustSay": ["成熟度", "每日上限", "禁忌族群＋問專業"],   // L3 三件事，少一件不准出庫
  "evidence": { "source": "PubMed 40918053", "year": 2025, "population": "18-65歲155人", "effect": "小(d=0.2)" },
  "verifiedAt": "2026-07-29"
}
```

**關鍵**：`timeToEffect`／`solutionType`／`effortCost` 三個標籤就是「因人因時」的把手。

## 二、四張牌怎麼讀出來（不靠問卷、從對話與記憶）

| 牌 | 讀什麼 | 從哪裡來 |
|---|---|---|
| **人** | 年齡、慢性病、在吃的藥、活動量、飲食習慣 | 記憶側寫、個人資料卡、健康資料 |
| **境** | **幾點問的**、季節天氣、住哪裡 | 系統時間（她本來就知道）、地區設定 |
| **心** | **急不急**、壓力大不大、情緒 | 語氣詞（「快受不了」「已經三天沒睡」）＋提問時間 |
| **史** | 以前推薦過什麼、他有沒有做、有沒有效 | 回訪紀錄（效果檔案） |
| **⭐偏好** | 願意吃保健品嗎？信中藥嗎？只想改生活？ | ①他自己說過的（「我不想吃藥」「我都喝中藥」）②回訪結果（推過保健品他沒買＝不接受）③**不知道就問一句** |
| **⭐可執行** | 他有時間嗎？要輪班嗎？走得動嗎？要顧小孩／顧老人嗎？ | 側寫（職業、作息）＋對話（「我三點就要起來顧我媽」） |

**不知道就問一句**（⓪-D-2 問診分寸已寫死）：
> 「你比較想先從調整作息這種慢慢來的方式試試，還是想找個今晚就能有點幫助的？」
一句話就能定調，不必問卷。

## 三、挑選規則（安全先剔除，再依人排序）

**第一關 · 安全過濾（硬性、不可被排序翻盤）**
- 有禁忌族群命中 → **整個方案剔除**（腎功能不佳 → 鎂直接拿掉，不是降權）
- L4/L5 → 不進推薦池，只走轉介
- 藥物交互作用（紅麴×降血脂藥）→ 剔除或強制「先問藥師」

**第二關 · 依人排序（軟性）**

| 訊號 | 怎麼調 |
|---|---|
| 半夜問／講「快受不了」 | 今晚檔升到最前面，慢養檔往後 |
| 白天問、語氣平和 | 慢養檔當主推，今晚檔給一個當甜頭 |
| 說過不想吃藥丸 | 保健品類**降到備援**，行為調整＋食補升前 |
| 說過在喝中藥 | 中醫調理類不排斥（但**必問有沒有跟西藥一起吃**→ 交互作用） |
| 輪班／照顧者／時間破碎 | `effortCost` 高的方案降權（「固定起床時間」對輪班的人是做不到的正確答案） |
| 活動量低、走不遠 | 運動類方案降權或改成坐著能做的版本 |
| 回訪說過沒效 | 該方案降到最後，換階梯下一級 |

**第三關 · 輸出**：主推 1 個 ＋ 備援 2 個（一個是「主推被禁忌擋掉時的替代」、一個是「試了沒效的下一步」）＋ 回訪鉤子。

## 四、同一題三個人 · 三種答案（這是驗收標準）

**症狀都是「最近都睡不好」——**

### A · 42 歲上班族，晚上 11 點問，語氣煩躁「快受不了了」
> 讀牌：急（半夜＋急迫詞）／時間破碎／可接受吃東西
> 排序：今晚檔優先，`effortCost` 低的優先
- **主推（今晚）**：睡前一小時把手機放遠一點、洗個溫水澡讓體溫降下來——今晚就能做
- **備援 A（一週）**：這一兩年有研究是找像你這樣睡不好的上班族做的，睡前補鎂大概能讓困擾減輕一點，效果不大、不是人人有感；台灣營養師建議一天不超過 250 毫克，吃多會拉肚子，你如果有腎臟或血壓的狀況要先問過專業
- **備援 B**：下午之後不碰咖啡
- 回訪：三天後問「這幾天有沒有比較好睡？」

### B · 68 歲退休長輩，早上 10 點問，語氣平和
> 讀牌：不急／時間充裕／文化上偏好食補／可能在吃慢性病藥
> 排序：慢養＋食補優先，保健品降權（多重用藥風險）
- **主推（慢養）**：白天多出去曬曬太陽、走一走，晚上比較好睡
- **備援 A（食補）**：深綠色蔬菜、堅果、香蕉本來就有鎂，從吃的補最安全
- **備援 B**：睡前泡個腳、固定時間上床
- **不主動提鎂錠**（他可能在吃慢性病藥，保健品要先問藥師才提）
- 回訪：一週後問

### C · 38 歲照顧者，半夜 2 點問，講「我媽三點要起來上廁所，我根本睡不飽」
> 讀牌：急＋**睡眠被切碎不是失眠**（真問題不同！）／`effortCost` 高的全部做不到
> 排序：先重新定義問題，再給做得到的
- **主推**：這不是你睡不著，是你根本沒得睡——先接住這件事
- **備援 A（今晚）**：把你自己的睡眠切成兩段來顧（她起來前先睡一段），比硬撐整夜好
- **備援 B（可求助）**：喘息服務可以讓你補眠，要不要我幫你記著、你有空去問問看
- **絕不建議**：「固定時間起床」「睡前放鬆一小時」——她根本沒有那一小時
- 回訪：問她自己撐不撐得住（照顧者的健康也是我們的事）

**驗收尺**：這三段話**互相不能替換**。任何一段換到另一個人身上會顯得答非所問——做到這樣才叫因人因時因地。

## 五、跟現有機制怎麼接（工程落地）

1. `engine/health_topics.json` 每題從「一段注入文」擴成「方案池 + 共用紅線」
2. `health_kb.py` 新增挑選層：讀四張牌 → 安全剔除 → 排序 → 只把**主推＋兩個備援**注入（不是把整池塞進去，會淹沒）
3. 說明書那層只留判準（怎麼講、什麼不能講），**選哪個方案交給程式**——這樣可測、可稽核、不靠模型自覺
4. 考卷加「同題不同人」變體題組：同一句「我睡不好」配 A/B/C 三個人設，**驗三個答案真的不一樣且都安全**

## 六、誠實記下的限制

- **偏好與可執行性靠對話累積**，第一次見面時她所知不多——這時就照 ⓪-D-2 問一句，不要硬猜。
- **中醫調理類我們目前沒有可信來源庫**。要納入必須另做一輪調研（台灣中醫藥司、有實證的方劑），在那之前她只能說「中藥的部分我不熟，你要不要問中醫師」——**不准硬掰**。
- 「同題不同人答案不同」目前**查無市場先例**（睡眠 App 的分層都靠使用者自己選目標，不是從對話讀）。這是我們的差異化，也代表**沒有前人的失敗經驗可借**，上線後要盯真實效果。
