## 推薦架構（方案 A：Rive ＋ wLipSync）

```
Gemini 24kHz 即時聲音 ──┬── 喇叭播放（手機本機）
                        └── wLipSync（瀏覽器內即時分析）
                              ↓ 每一格畫面：五種母音嘴形權重＋音量
                        Rive 角色狀態機（寧寧新形象）
                              ↑
大腦情緒標籤（開心/安撫/中性）─┘   待機呼吸、眨眼、小動作＝角色自己跑
```

**對照 Edward 四條邊界逐條檢核：**

| 邊界 | 檢核 |
|---|---|
| ① 全手機端運算 | ✅ 嘴形分析＋角色渲染全在手機瀏覽器內跑；雲端只送聲音和情緒標籤（幾個字節） |
| ② 真產品化、非半吊子 | ✅ 同款打法在多鄰國 AI 視訊通話（上億支手機）出貨中；嘴形是「五母音分類」不是廉價的音量拍嘴（那是我們的保底線）；VTuber 全產業標準即此等級 |
| ③ 成本取代顯卡 | ✅ 顯卡月租（每卡 NT$11,304/月、隨用戶線性加卡）→ 一年授權費合計 <NT$1.5 萬固定（Rive 編輯器一席訂閱；播放核心與嘴形件全 MIT 免費）；每分鐘邊際成本 = 0 |
| ④ PMF 無「買顯卡」概念 | ✅ 用戶規模與顯卡完全脫鉤；IRIAM 證明「雲端只送動作資料、每支手機自己畫」這個架構在低階機直播都夠用 |

**兩個備選與升級路：**
- 方案 B：Live2D＋wLipSync——動漫感更暖、台灣建模人才好找（VTuber 生態）、年營收 210 萬內免授權費；正式工期較長（6-10 週）。可作女巫比稿時的美術路線之一。
- 未來升級：台語自架語音（BreezyVoice-Taigi）上線後，伺服器端能拿到逐音素時間軸——屆時可照抄多鄰國原版做法（伺服器下發嘴形時間表、更準），跟現架構無縫銜接。
- 3D（VRM）與純抽象動態不進第一版（發熱風險最高／長輩偏好墊底）。

**工期與成本（合併 Codex 8/6 中午評審的修正）：**

| 階段 | 內容 | 時間 |
|---|---|---|
| 試作 | 佔位角色＋wLipSync 接真聲音串流，在 iPhone SE2 真機量幀率/發熱/耗電；中文嘴形準度實測（不準就退保底線：庫內既有音量＋頻譜法，美術資產共用） | 1-2 週 |
| 正式 | 寧寧新形象美術與綁定＋後端拆綁（通話改成「可只領語音」——不拆這個，光換畫面一毛都省不到）＋商店文案/舊戶緩衝配套＋iPhone 全鏈驗收 | 6-8 週全包 |

**風險與坑（誠實列）：**
1. 舊 iPhone 實際幀率/發熱查無現成數據——PoC 第一週就量掉，這是唯一的硬不確定。
2. Rive 專業動畫師在台人才池小（Live2D 好找得多）——女巫比稿時兩條美術路線並提。
3. 嘴形×情緒狀態機複雜度要控制（多鄰國的分層法：嘴一層、姿態一層，直接抄）。
4. 後端「語音＋臉綁一起領」的拆綁是工程主體（Codex 已盤出完整清單，見策略報告附錄 D3）。
5. bitHuman 放進觀察名單（半年後若放寬到 iPhone 14/15 級再評）；Simli 類 API 維持「只驗證不依賴」。

## A1. 四條路成熟度表

### 路① bitHuman CPU Avatar SDK（最接近商用的一條）

| 項目 | 內容 |
|---|---|
| 技術狀態【實查】 | 真實 SDK、非論文 demo。25fps 音訊驅動唇形，宣稱端到端延遲 <200ms，支援 CPU（樹莓派~伺服器）、NVIDIA GPU、Apple Silicon。分兩個模型：**Essence**（單張照片/影片先線上生成 `.imx` 檔，之後純推理）與 **Expression**（不需預先生成，即時吃任意臉圖）。[GitHub](https://github.com/bithuman-product/bithuman-sdk-public) / [docs](https://docs.bithuman.ai/introduction) |
| 手機實測證據【實查】 | 官方文件明寫 iOS 端**最低要求 iPhone 16 Pro + iOS 26**（Essence）；Expression 甚至要求 NVIDIA GPU 或 Mac M3+。品質分兩級：**Quality（要 GPU）／Light（任何 CPU）**——照沐寧的舊機/中階 Android 情境，能拿到的只會是降級版 Light |
| 產品化先例【實查】 | 美術館 kiosk（MINT Museum，Mac Mini）、企業客服（Ivoclar）、展會互動機（NRF、10 台 kiosk）——**全部是固定硬體/企業場景**，查無任何上架 App Store 的消費級手機 App 在用 |
| 授權費【實查】 | 免費 99 credits/月；自架 1 credit/分鐘、雲端 2 credits/分鐘；每角色一次性 250 credits。SDK 走 MIT 或 source-available |
| 風險【實查+推斷】 | 2023 年成立、募資 $4.3M、12 人團隊——早期新創，長期維護與機型支援加碼的不確定性偏高 |

### 路② 手機端 3D 高斯潑濺（Gaussian Splatting）人頭

- 2024-2026 論文密集（GaussianTalker、PGSTalker、Audio-Plane、GaussianEmoTalker 等）都宣稱 real-time，但**全部只在桌機 RTX 3090/4090 級顯卡上跑**，論文無手機數據【實查】。
- 真手機數字只有「純渲染、非說話」：SplattingAvatar（CVPR2024）手機約 30fps；Instant Skinned Gaussian Avatars（2025）瀏覽器內 iPhone 13 Pro 實測 40-50fps——都是骨架動作、不是語音驅動嘴形【實查】。
- 最接近的「手機＋說話」＝阿里 TaoAvatar（CVPR2025）：Android 端 90fps 且有聲音驅動表情，但**建一個角色要 59 台校正相機的攝影棚**，非消費級流程；未見進入真實產品【實查】。
- 結論：渲染引擎能上手機是真的，「說話＋一鍵建角色」還沒接上，無商用 SDK 包裝。

### 路③ 小型嘴形神經模型蒸餾進手機 NPU

- 查無成熟輕量化蒸餾模型；Wav2Lip 已被視為過時，業界最新商用（sync.so sync-3）反而往**雲端更高畫質**走、不是往端側輕量化走——與 Edward 要的方向相反【實查】。這條路**目前基本不存在**。

### 路④ Apple 官方生態

- ARKit 52 組臉部參數：成熟、60fps、端側——但那是「鏡頭追真人臉去驅動角色」（Memoji 模式），跟「只有聲音要生出臉」是反向問題。可借用的做法＝接一個「聲音→52 參數」的小模型驅動**風格化 3D 角色**，不是像素級擬真臉【實查】。
- Apple Persona（Vision Pro 的神經生成臉）：visionOS 26 畫質大升、蘋果也收購了頭像新創——方向在投資，但**僅限 Vision Pro，無下放 iPhone 跡象**【實查】。

## A2. 判斷

**2026 年 8 月，手機端神經生成擬真臉＝還早（對沐寧的實際用戶機隊尤其如此）**：①唯一真產品（bitHuman）從設計上就沒打算相容舊機 ②中階 Android 四條路全掛零 ③「能渲染」與「會說話＋易建模」還是兩件沒接上的事。

**最接近可用的替代**：聲音→表情參數驅動的骨架偶動畫（Live2D 級 2D 或 blendshape 級 3D 風格化角色），今天就能全機種跑、延遲低、成本趨近零、開源與商用先例成熟。差的是「像素級像真人」——這是品牌/產品決策，不是技術缺口。

**bitHuman 進觀察名單**：定位「未來旗艦機專屬加值選項」，若半年後放寬到 iPhone 14/15 或中階 Android 再重評；現在押它等於把大部分用戶排除在新臉之外。

**一句話**：手機端神經生成擬真臉還太早（信心度：高）；務實路線是放棄「神經生成」框架、改走聲音驅動的骨架偶動畫，今天就能真產品化。

## B3. 三套組合架構

**方案 A：Rive＋wLipSync（🥇 推薦）**——總授權年成本約 NT$3,500-12,500、零跟用戶數走的費用；PoC 1-2 週、正式 4-8 週（不含後端拆綁）；最大風險＝Rive 動畫人才在台較少、狀態機複雜度要控（抄多鄰國分層法）；效能依據＝向量渲染＋官方低階機模式＋多鄰國億級手機出貨實績。退路：wLipSync 中文不準就退庫內音量頻譜法，美術資產完全共用、無沉沒成本。

**方案 B：Live2D＋wLipSync**——嘴形對接更簡單（Live2D 標準參數直接映射）、美術人才最好找（VTuber 模型委製行情 NT$3-15 萬）；現階段發佈免費；正式 6-10 週；風險＝Web 版無手機基準、核心閉源。

**方案 C：VRM＋three-vrm＋wLipSync**——全鏈 $0、開源參考完整、跟五母音制天作之合；但發熱最高、容易掉進「3D VTuber 感」；未來要鏡頭視角/頭部跟隨才選。

**一句話**：Rive＋wLipSync 可在 WKWebView 內做出產品級寧寧，年授權 <NT$1.5 萬、砍掉整條顯卡月租；架構可行性信心【高】、舊機實測【中】（1-2 週 PoC 在 SE2 真機量掉）。

## C2. 真產品驗證路線排名

1. **2D 風格化角色＋狀態機動畫、手機端渲染（Rive/Live2D 路線）**——多鄰國（5 億下載＋AI 視訊通話上市）、IRIAM（低階安卓直播實證）、Wysa。
2. Unity 3D＋blendshape——Replika（3,500 萬用戶）、REALITY、Cotomo、Grok Ani；代價是 App 體積、電量、整條 3D 美術線。
3. **雲端生成式影片（沐寧現在這條）**——只有 Character.AI 在衝且即時版停在論文（每通話 2 張 GPU）；**沒有任何消費級陪伴 App 靠這條路規模化成功**。
4. 乾脆不做臉——Talkie/PolyBuzz（億級下載、通話時靜態卡）、ElliQ。證明「畫面動不動」不是陪伴產品成敗變數。

## C3. 對沐寧的啟示

1. **最像我們的產品＝多鄰國 AI 視訊通話**，解法完全公開可抄。
2. **IRIAM 是架構同構的第二證人**：雲端只送動作資料、每支手機自己畫＝正是「把 4090 臉機換掉」的目標架構，且低階機扛得住。
3. **長輩不需要擬真臉**：care.coach 卡通狗貓拿到臨床實證、ElliQ 研究後刻意拿掉臉——風格化對長輩反而更親。
4. **反面證據**：三星 Sam 十年未上市；Character.AI 即時影片停在論文。「雲端顯卡生成擬真臉」是全市場繞開的孤路。
5. 捨不得質感的中間路＝Grok Ani 式「3D＋端上動作生成」，但工程與美術管線對兩人團隊不是首選。

**一句話**：被真產品驗證最多次、與沐寧同構的路＝「嘴形參數＋手機端風格化角色渲染」（多鄰國原樣照抄）；雲端顯卡生成擬真臉是全市場繞開的孤路。信心度 85%。
